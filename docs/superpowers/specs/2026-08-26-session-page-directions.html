Session Page Directions

The current page showcases the agent. Your feedback says it should showcase the feed, and let the agent be felt through what changes, not what's labeled. Three layout directions and three subscribe choreographies to decide between.

2026-08-26 · decisions marked recommended are my leaning, not a default

The critique, distilled principles

P1 The feed is the product. The agent is choreography. "You + your agent", the explainer sentence, the prompt chips: all of it is UI about the mechanism. The episodes and the listening experience are the content. Everything meta earns its pixels or goes.
P2 Trust comes from watching content change. A row appearing with a ticking percentage is more convincing than any "agent mode" banner. Keep one small, honest trace of agent activity; delete the rest of the chrome.
P3 The first-run job is subscribing. A created feed nobody subscribes to is a dead end. The page's first state, and the agent's next move after create_feed, should both point at one thing: get this feed into a podcast app.

Decision 2 · The subscribe moment pick one

How the agent helps the user actually subscribe, right after create_feed. The sequence I'd aim for:

  1. agentcreate_feed → lands on the session page (state 1).
  2. siteTool result tells the agent: "Next, help the user subscribe. Call help_subscribe."
  3. agenthelp_subscribe → the page highlights the subscribe card and tries to copy the RSS link to the clipboard; the tool returns the per-app links and a short instruction to relay.
  4. agent → user"Your feed is ready. I've copied the RSS link; tap Apple Podcasts on the page, or paste the link into any podcast app."
  5. userTaps a button; the OS hands the feed to the podcast app. Done: state 2.
OptionWhat it isVerdict
O1 · Tool choreography New help_subscribe tool as above; create_feed's result names it as the next step. The agent stays the narrator; the page does the work. recommended · pairs with C; testable; degrades to O2 if the agent skips it
O2 · Page-only No new tool. State 1 auto-highlights the subscribe card on arrival; the agent just says "tap a button on the page." Safe floor. Ship it inside C regardless; O1 layers on top
O3 · Deep-link push A tool that navigates the tab to podcast://… itself, so the podcast app opens without the user touching anything. "Computer use" via URL scheme. Spicy demo beat, but custom-scheme navigation from agent in-app browsers is unproven and a failed nav strands the tab. Test in Codex first; behind a flag if it works
Technical risk on the clipboard: navigator.clipboard.writeText requires document focus and often a user gesture; a tool call from an agent may have neither, and Safari is strictest. So the clipboard copy in O1 is best-effort, and the page never claims it happened unless it did: the "I copied it, just paste" line renders only on success, and the fallback is a big visible Copy button. This is also why O2 ships inside every option.
