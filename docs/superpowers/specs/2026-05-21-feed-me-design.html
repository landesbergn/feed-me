Design Spec — v1.0

Feed Me

A personal podcast feed of AI-narrated articles · 2026-05-21

Feed Me is a service that turns saved articles into a personal podcast feed. You share a URL via the iOS Share Sheet; within ~60 seconds an AI-narrated episode appears in the podcast app of your choice. Architected for personal use first, with a clear path to multi-user public product later.

1. Goals & non-goals

Goals

  • Share any URL from any iOS app and have an audio episode in your podcast app within ~60 seconds.
  • Listen in the podcast app of your choice (Apple Podcasts, Overcast, Pocket Casts, etc.) via a standard RSS feed.
  • Each user gets a personal, unguessable feed URL; new submissions append episodes.
  • Audio is a faithful, lightly-formatted read of the article — no editorializing, no host persona.
  • Cheap, simple to operate, and reliable for personal use; architected so going public later is incremental work, not a rewrite.

Non-goals (v1)

  • No PDF, file, or arbitrary text input — URLs only.
  • No in-app player. We produce an RSS feed and audio files; listening UX is delegated to existing podcast apps.
  • No web/Android/Mac client. iOS Share Sheet only.
  • No summarization, discussion, multi-host, or AI commentary.
  • No multi-voice per feed, no per-episode voice override.
  • No search, transcripts, social sharing, or analytics.

2. User flows

2.1 First-time setup (once per user)

  1. Visit /settings, sign in (single password, MVP).
  2. Copy your RSS feed URL and paste it into your podcast app as a custom feed subscription.
  3. Tap the Install Shortcut link from your iPhone; Apple Shortcuts asks for your API token (shown on the settings page) and saves it inside the shortcut.
  4. Pick a voice (default: shimmer).

2.2 Saving an article

  1. In Safari (or any iOS app), tap Share → Send to Feed Me.
  2. The Shortcut POSTs the URL to the API; you see a brief success toast.
  3. ~30–90 seconds later, the new episode appears in your podcast app on next refresh.

2.3 Listening

Standard podcast app behavior. Newest episode at the top of the feed. Your podcast app handles downloads, playback position, speed, and local cleanup.

3. Architecture

One Fly.io machine runs a single Node.js process containing both the HTTP server and the background worker. SQLite (on a Fly volume) holds all state. Cloudflare R2 stores MP3 audio. Two vendors, one log stream.

4. Processing pipeline

Each ingested URL becomes one episode row. The worker drives it through five steps, each tracked as a jobs row. Steps are idempotent; on transient failure they retry up to 3 times with exponential backoff before marking the episode failed.

1fetch_extract~3–5s

HTTP GET the URL with a real-browser User-Agent. Run Mozilla Readability on the HTML to get title, byline, siteName, and clean article text. Compute word count. If word_count > 20,000, fail the episode with "Article too long (over 20k words)". Run the paywall heuristic (§5). If paywalled, schedule step 2; otherwise skip to step 3.

2fetch_archive (conditional)~3–6s

Call https://archive.org/wayback/available?url=<URL>. If a snapshot exists, fetch it and re-run Readability. Mark used_archive=true on the episode. If the archived version still trips the paywall heuristic (or no snapshot exists), fail the episode with "Couldn't extract article (paywalled and not in Wayback)".

3build_script<100ms

Construct the TTS script from a template, no LLM: "From {siteName}{byline ? ', by ' + byline : ''}. {title}.\n\n{body}". Body is the Readability-cleaned plain text. Normalize whitespace and ensure paragraph breaks are preserved as natural pauses.

4tts~30–90s

Call OpenAI TTS with the user's voice setting. Stream the response to a temp file. Reject scripts exceeding the OpenAI per-request limit by chunking on paragraph boundaries and concatenating the resulting MP3 segments before upload.

5upload~1–3s

PUT the MP3 to R2 at key audio/{user_id}/{episode_public_id}.mp3. Read Content-Length for audio_size_bytes; estimate duration_seconds from byte length and bitrate (or parse the MP3 header). Update episode: status='ready', ready_at=now(), store the R2 key. The RSS feed picks up the new episode immediately on next request.

5. Paywall handling

Two heuristics trigger the Wayback fallback after step 1:

  • Length signal: extracted body has fewer than 200 words.
  • Phrase signal: body contains one of: "subscribe to continue", "sign in to read", "this article is for subscribers", "create a free account", "premium content", plus a small denylist of known paywall site banners.

Either signal sends the episode to step 2 (Wayback). The fallback is ethical (it uses the Internet Archive's official Availability API, not scraped clones), but coverage is imperfect — articles published in the last 24 hours often aren't archived yet.

Known limitation: when both the direct fetch and Wayback fail, the user sees a failed episode in settings with a clear error. A future "Paste text" Shortcut variant (in backlog) will cover paywalled content not in Wayback.

6. Data model

SQLite, three tables. Times are unix epoch milliseconds. public_id columns are UUIDv7 strings used in URLs to prevent enumeration; internal id stays an integer for ergonomic joins.

CREATE TABLE users (
  id              INTEGER PRIMARY KEY,
  email           TEXT NOT NULL,
  voice           TEXT NOT NULL DEFAULT 'shimmer',
  feed_token      TEXT NOT NULL UNIQUE,    -- 32 random bytes, base64url, used in feed URL
  api_token_hash  TEXT NOT NULL,           -- sha256 of bearer token, plaintext never stored
  created_at      INTEGER NOT NULL
);

CREATE TABLE episodes (
  id                INTEGER PRIMARY KEY,
  public_id         TEXT NOT NULL UNIQUE,  -- UUIDv7, used in audio URL + RSS guid
  user_id           INTEGER NOT NULL REFERENCES users(id),
  url               TEXT NOT NULL,
  url_hash          TEXT NOT NULL,         -- sha256(user_id || normalized_url), for dedup
  status            TEXT NOT NULL,         -- pending | processing | ready | failed
  title             TEXT,
  byline            TEXT,
  site_name         TEXT,
  word_count        INTEGER,
  audio_key         TEXT,                  -- R2 object key
  audio_size_bytes  INTEGER,
  duration_seconds  INTEGER,
  used_archive      INTEGER NOT NULL DEFAULT 0,
  error_message     TEXT,
  created_at        INTEGER NOT NULL,
  ready_at          INTEGER,
  UNIQUE(user_id, url_hash)
);

CREATE TABLE jobs (
  id            INTEGER PRIMARY KEY,
  episode_id    INTEGER NOT NULL REFERENCES episodes(id),
  step          TEXT NOT NULL,             -- fetch_extract | fetch_archive | build_script | tts | upload
  status        TEXT NOT NULL,             -- pending | running | done | failed
  attempts      INTEGER NOT NULL DEFAULT 0,
  last_error    TEXT,
  scheduled_at  INTEGER NOT NULL,
  updated_at    INTEGER NOT NULL
);

CREATE INDEX idx_jobs_pending ON jobs(status, scheduled_at);
CREATE INDEX idx_episodes_user_ready ON episodes(user_id, ready_at DESC) WHERE status = 'ready';

7. API contracts

POST /api/ingest authenticated

Auth: Authorization: Bearer <api_token>.

// Request
{ "url": "https://example.com/article" }

// 200 OK — new episode queued
{ "episode_id": "0190ab...", "status": "pending", "deduped": false }

// 200 OK — already in this user's feed
{ "episode_id": "0190ab...", "status": "ready",   "deduped": true }

// 400 — malformed URL
{ "error": "invalid_url" }

// 401 — missing or bad token
{ "error": "unauthorized" }

Response time target: < 200ms. Heavy work happens in the background worker.

GET /feed/:token.xml public

No auth header; the token in the URL is the auth. Returns valid podcast RSS 2.0 with the iTunes namespace. Includes only episodes with status='ready', ordered newest first. Caches at the edge for 60s.

GET /settings authenticated

Minimal HTML settings page. Shows feed URL, API token, Shortcut install link, voice picker, recent episode list (with errors for failed ones). MVP auth: a single password in env (SETTINGS_PASSWORD) via HTTP basic auth — replaced with magic-link auth when going public.

R2 audio URLs public

Audio is served directly from a public R2 bucket via a custom domain, e.g. https://audio.feedme.app/audio/{user_id}/{episode_public_id}.mp3. Anyone with the URL can stream it (same security model as every podcast on the internet); unguessable keys keep the bucket effectively private to feed subscribers.

8. Auth & security

  • API token: 32 random bytes, base64url-encoded. Stored as a sha256 hash; the plaintext is shown to the user once on the settings page. Sent as a Bearer token.
  • Feed token: 32 random bytes, base64url. Stored plaintext (no out-of-band check possible — the token itself is the credential). Treated as a capability URL: anyone with it can read your feed.
  • Settings access (MVP): HTTP basic auth gated by SETTINGS_PASSWORD env var. Replaced by magic-link login (Resend or Postmark) before the first non-owner user.
  • R2 bucket: public read on the audio/ prefix, no listing. Keys contain UUIDv7s, so enumeration is infeasible.
  • SSRF guardrail: URL fetching uses a strict allowlist of schemes (http/https) and blocks private IP ranges (10/8, 192.168/16, 172.16/12, 127/8, fe80::/10, etc.) to prevent the ingest endpoint from being abused to probe internal networks.
  • Rate limit: per-token simple sliding window — 30 submissions / hour, 200 / day. Generous for personal use, sane upper bound if a token leaks.

9. Error handling

FailureBehavior
Network/HTTP error fetching URLRetry 3× with backoff; then fail episode with the HTTP status.
Readability returns empty / paywalled bodyGo to fetch_archive step (§5).
Wayback has no snapshotFail episode: "Couldn't extract article (paywalled and not in Wayback)."
Article over 20k wordsFail episode: "Article too long (over 20k words)."
OpenAI TTS error (rate limit, transient)Retry 3× with backoff; then fail episode.
R2 upload errorRetry 3× with backoff; then fail episode.
Worker process crash mid-stepOn restart, any jobs.status='running' older than 5 min is reset to pending and re-attempted.

Failed episodes appear in the settings page with their error message so you know what went wrong. The Shortcut response from /api/ingest only reflects acceptance, not eventual outcome — surfacing async failures back to the Shortcut as iOS notifications is a v1.1 enhancement.

10. Deployment

  • Fly.io: one machine, shared-cpu-1x, 256MB RAM, with a 1GB volume mounted at /data for SQLite. fly deploy from a standard Node Dockerfile.
  • Cloudflare R2: one bucket with public access on audio/ prefix, custom domain mapped.
  • Env vars: OPENAI_API_KEY, R2_ACCESS_KEY_ID, R2_SECRET_ACCESS_KEY, R2_BUCKET, R2_PUBLIC_BASE_URL, SETTINGS_PASSWORD, OWNER_EMAIL.
  • Migrations: SQL files in migrations/, applied in order on startup; tracked in a _migrations table.
  • Backups: nightly litestream replication of the SQLite file to R2 (optional but cheap insurance).
  • Logs: stdout to Fly's log stream; structured JSON (pino).

12. Testing

  • Unit tests: URL normalization, paywall heuristic, Readability output shape, RSS XML rendering, SSRF guardrail.
  • Integration tests: end-to-end POST /ingest → DB row → mocked TTS → R2 mock → feed XML contains episode. Run against an ephemeral SQLite file and an in-memory R2 stub.
  • Fixture corpus: a small set of saved HTML pages (paywalled, ad-heavy, simple blog, long-form, edge cases like non-English) to regression-test extraction.
  • Manual smoke test: after deploy, send 3 real URLs via the Shortcut and confirm episodes appear in a podcast app within 90s.

13. Out of scope & backlog

Explicitly out of scope for v1

  • PDF / file uploads.
  • Raw-text input ("paste this text") Shortcut variant.
  • Magic-link or OAuth login.
  • Per-episode voice override.
  • LLM cleanup or summarization.
  • Multi-part splitting of very long articles (currently capped at 20k words and rejected).
  • iOS notifications on async failure.
  • Episode artwork from og:image.
  • Streaming TTS / progressive playback.
  • Search, transcripts, export.

Backlog (rough order)

  1. v1.1 Async failure notifications back to the Shortcut (iOS push or email).
  2. v1.2 "Paste text" Shortcut variant for paywalled content not in Wayback.
  3. v1.3 Episode artwork from og:image.
  4. v2.0 Magic-link auth, multi-user signup, public landing page.
  5. v2.x PDF input. Per-episode voice. ElevenLabs as a premium voice tier.
