Spec · v3.12

Seamless agent sharing

Feed Me · 2026-06-07 · spec

Make "send this article to my feed" a one-shot, zero-question action for an AI agent. Today an agent that does not already hold the feed URL has no safe, documented way to get it: it either asks the user every time or, worse, tries to rediscover the URL by scanning history and probing candidate feeds. This spec fixes that with one additive endpoint and a re-sequenced AGENTS.md that tells the agent to capture the feed URL once, from the prompt the user already pastes, and never rediscover it.

1 · Why

A real session: the owner told his agent "send the new Blackbird Spyplane to my Feed Me feed" with no feed URL in the conversation. The agent had no saved URL and no documented recovery path, so it scanned past transcripts and probed eight candidate feeds to find the live one. That behavior was expensive (many wasted calls), and a safety classifier correctly blocked the final POST because the target feed had been inferred, not supplied, forcing a confirmation round-trip the owner should never have seen.

Two root causes:

  • The feed URL is never persisted. The copy-paste prompt on the feed page already contains the URL, but nothing tells the agent to save it, so every new session starts from zero.
  • There is no cheap "is this my feed?" call. GET /u/<secret>/episodes returns 405 Method Not Allowed (only POST and the per-slug GET exist), so an agent wanting to confirm a feed has to fetch and parse feed.xml.

Audience: both memory-having agents (Claude Code, Cowork, which persist the URL) and stateless chat agents (re-pasted each time). The design serves both.

2 · What we're building

  1. A new GET /u/{secret}/episodes endpoint that lists the feed's episodes plus feed info and remaining quota, as JSON: path-secret auth, no cookie, the same {"error","message"} contract as the other agent endpoints. Doubles as the cheap feed-exists check (404 when the secret is unknown).
  2. An AGENTS.md rewrite that leads with the happy path, adds a "Step 0 · remember this feed" instruction, adds an explicit "if you don't have the URL, ask, never guess, scan, or probe" rule, and documents the new endpoint.
  3. A one-clause change to the copy-paste prompt in templates/_setup_instructions.html so the agent is told to save the feed URL on first contact.

No change to the cookie-authed /share path, the POST /episodes creation logic, the rate limiter, storage, or the RSS feed.

3 · The list / confirm endpoint

New route in app.py, registered before the existing GET /u/{secret}/episodes/{slug} (distinct path, so ordering is not load-bearing, but keep them adjacent for readability). Mirrors episode_status_api: synchronous, path-secret auth, never reads or sets the session cookie, returns _agent_error(404, "not_found", …) when the secret has no feed. 

GET {base}/u/<secret>/episodes

200 OK
{
  "feed_page": "{base}/u/<secret>",
  "feed_url":  "{base}/u/<secret>/feed.xml",
  "voice": "shimmer",
  "remaining": 3,
  "episodes": [
    { "slug": "ZMs8QEngXImu06nE",
      "title": "Hiking-sandal realness",
      "status": "ready",
      "ts": 1780857382,
      "audio_url": "{base}/u/<secret>/audio/ZMs8QEngXImu06nE.mp3" }
  ]
}

Field rules

  • Scope: the whole feed (agent shares, phone shares, and the seeded welcome), most-recent-first, the same set feed.xml and the settings page show. Built from storage.list_episodes, which already sorts by mtime descending.
  • Cap: the 20 most recent episodes, documented in AGENTS.md. (The settings page uses 30; 20 is plenty for an agent confirming a feed and keeps the payload small.)
  • Per-episode fields: slug, title (may be null), status (pending|ready|failed, derived by list_episodes), ts. Add audio_url only when status == "ready" (same rule as the per-slug endpoint). Add error only when status == "failed".
  • Never leak internals: do not emit mtime, audio_bytes, has_audio, source_url, or via. Build each episode dict explicitly; do not pass the raw storage record through.
  • Feed info: voice from storage.get_settings; feed_page and feed_url built from APP_BASE_URL and the secret.
  • remaining: AGENT_DAILY_CAP - len(_agent_episodes_in_window(secret, now)), the same quota the POST reports, so an agent can see its budget before sharing, not only after. Floor at 0 defensively.
The secret is in the path but must never appear in logs or analytics values. Follow the existing agent endpoints: no _track call that records the raw secret, and no logging of the URL. (A page_view-style track keyed by secret is fine if it matches how the other agent endpoints already attribute, i.e. not at all today; keep this endpoint untracked.)

4 · AGENTS.md rewrite

Same facts, re-sequenced so the cheapest correct path is first and the failure modes from this session are named. templates/agents.md is substituted with a plain .replace("{base}", …) (per the repo gotcha: not Jinja, not str.format), so the rewrite keeps using the literal {base} token and adds no new braces outside the JSON examples it already contains.

  1. TL;DR at the top (three lines): you have a feed URL of the form {base}/u/<secret>; to narrate an article, POST it, poll until ready, done. One curl.
  2. "Step 0 · Remember this feed": on first contact, save the feed URL to your durable memory so future requests need no URL and no questions. Wording is ecosystem-neutral ("your durable memory or project config"), with Claude Code's CLAUDE.md / memory file named as a concrete example. The user's pasted prompt already carries the URL; capture it once.
  3. "If you don't have the feed URL, ask the user." Stated in the Auth section and again in Etiquette: never guess the secret, never scan history or prior transcripts, never probe candidate feeds. This is the exact behavior that was blocked this session; naming it keeps well-behaved agents out of that trap.
  4. Document GET /episodes (list + confirm) beside the existing per-slug poll endpoint, noting the 20-item cap and that a 404 means "wrong or rotated URL, ask the user".
  5. Keep Add / Poll / Read-the-feed / Errors / Rate-limit / curl + Python examples. The Python example gains a one-line comment to persist feed for next time.

Copy constraint (repo-wide): no em-dashes in any user- or agent-facing text; the middot · is fine. Grep the rewritten file before shipping.

5 · The copy-paste prompt

In templates/_setup_instructions.html, the prompt text gains a persistence clause. From: 

I have a Feed Me podcast feed. To send an article to it, read
{base}/AGENTS.md and follow it. My feed page: {base}/u/<secret>.

to:

I have a Feed Me podcast feed. Save my feed page so you don't have to ask
again, then read {base}/AGENTS.md to send articles.
My feed page: {base}/u/<secret>.

The template keeps its Jinja {{ base_url }} / {{ secret }} variables; only the prose changes. The click-to-copy box and its script are untouched.

6 · Testing

TDD, no network, using the existing client fixture (temp DATA_DIR per test). New tests in tests/test_app.py:

  • Lists episodes: create a feed, share an article (or seed one), GET /u/<secret>/episodes → 200, body has episodes (the shared slug present), voice, remaining, feed_page, feed_url.
  • Ready vs not: audio_url appears only on a ready episode; a failed episode carries error and no audio_url.
  • No internals leak: response episodes contain none of mtime, audio_bytes, has_audio, source_url, via.
  • Bad secret: GET on an unknown secret → 404 with JSON {"error":"not_found", "message":…} (not HTML).
  • remaining tracks the cap: after N agent shares, remaining == AGENT_DAILY_CAP - N; reflects the same window the POST uses.
  • Cap at 20: with >20 episodes, exactly 20 most-recent are returned, newest first.
  • Copy guard: assert the em-dash character is absent from the rendered AGENTS.md and the prompt text.

7 · Out of scope

  • A downloadable Claude Code skill or MCP server pre-loaded with the feed URL (a good later add; more surface to maintain than the problem justifies now).
  • URL de-duplication / idempotency on POST (re-sharing the same URL still creates a new episode).
  • Any change to the cookie-authed /share flow, the rate limiter, storage, voices, or rotation.
  • A short-lived "claim code" handoff: the pasted prompt already carries the URL, so persistence solves the same problem without a new mechanism.

8 · Acceptance criteria

  • GET /u/<secret>/episodes returns the documented JSON for a real feed and a 404 {"error","message"} for a bad secret; no internal fields leak; remaining matches the POST's accounting.
  • AGENTS.md leads with the happy path, instructs the agent to persist the feed URL on first contact, forbids guessing / scanning / probing, and documents the list endpoint, with no em-dashes.
  • The feed-page prompt tells the agent to save the feed URL.
  • Full suite green (uv run pytest); a CHANGELOG.md entry and a v3.12 tag accompany the change.
  • End-to-end: a fresh agent given only the pasted prompt can save the feed, share an article, and confirm it landed, with no question to the user and no feed probing.
