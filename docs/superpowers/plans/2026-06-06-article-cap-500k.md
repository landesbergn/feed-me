# Article Cap 500k Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Raise the per-article cap from 100k to 500k characters without trading the clean "too long" failure for flaky mid-synthesis rate-limit failures.

**Architecture:** Three changes in `ingest.py`: the `MAX_BODY_CHARS` constant, a bounded `ThreadPoolExecutor` in `synthesize()` (`TTS_MAX_PARALLEL = 12`), and `OpenAI(max_retries=5)`. The worker bound keeps the burst sane; the SDK's 429 retry (with `Retry-After` honored) is the actual rate-limit correctness guarantee, since request *rate* depends on per-call latency which we cannot promise. Spec: `docs/superpowers/specs/2026-06-06-article-cap-500k.html`.

**Tech Stack:** FastAPI app, pytest with `fake_http`/`fake_openai` fixtures (`tests/conftest.py`), openai SDK 2.38.0 (client exposes `.max_retries`, verified), Fly.io deploy.

**Testing limits, understood up front:** with an instant fake client no test can verify requests/minute stays under 50; that is a timing property. The concurrency test proves the worker bound (peak in-flight <= 12), the retries test proves the config is set. The rate guarantee itself is only observable in production (Task 5).

```python
def test_synthesize_bounds_parallelism(monkeypatch):
    """With more chunks than TTS_MAX_PARALLEL, peak in-flight TTS calls stay
    at or under the bound, and output bytes stay in input order."""
    import threading
    import time

    known_chunks = [f"chunk-{i:02d}" for i in range(20)]
    monkeypatch.setattr(ingest, "chunk_text", lambda body, max_chars: known_chunks)

    class ConcurrencyFake:
        def __init__(self):
            self.lock = threading.Lock()
            self.in_flight = 0
            self.peak = 0
        @property
        def audio(self):
            return self
        @property
        def speech(self):
            return self
        def create(self, *, model, voice, input):
            with self.lock:
                self.in_flight += 1
                self.peak = max(self.peak, self.in_flight)
            time.sleep(0.05)  # hold the slot so overlap is observable
            with self.lock:
                self.in_flight -= 1
            return type("R", (), {"content": input.encode("utf-8")})()

    fake = ConcurrencyFake()
    monkeypatch.setattr(ingest, "openai_client", fake)

    audio = ingest.synthesize("any body", "shimmer")

    assert fake.peak <= ingest.TTS_MAX_PARALLEL
    assert audio == b"".join(c.encode("utf-8") for c in known_chunks)
```

## Addendum: OOM fix (same release, tag moves)

Task 5's first run OOM-killed the 1GB VM at 265k chars / 69 chunks (`anon-rss: 866MB`): `pool.map` submits every task up front and completed futures retain their ~3-5MB MP3 results until consumed (~300MB), then `b"".join` allocates a second full copy. At the 500k cap the audio buffers alone are ~1.1GB, so no VM size fixes the accumulate-then-join design. Spec §3 (amended) has the full reasoning. The fix: `synthesize(text, voice, out_path)` streams sequential batches of `TTS_MAX_PARALLEL` chunks to a temp file; `write_episode(audio_path=...)` atomic-renames it into place. Peak audio memory becomes one batch (~50MB) at any article length.

```python
def synthesize(text: str, voice: str, out_path: Path) -> None:
    """Stream MP3 audio for the full text to out_path.

    Renders chunks (chunk_text, sentence boundaries) in sequential batches of
    TTS_MAX_PARALLEL, appending each batch to out_path as it completes. The
    batches are the memory bound: one big pool.map would buffer every
    completed chunk's MP3 in its futures (the first v3.8 deploy OOM-killed
    the 1GB VM that way at 69 chunks); a batch holds at most ~12 x ~4MB.
    pool.map preserves order within a batch and batches run sequentially, so
    the file is in input order.

    Rate limit: the batch size bounds the burst, not requests/min (W workers
    at T s/call sustain W*60/T req/min, and per-call latency isn't promised);
    the correctness guarantee is the client's 429 retry with backoff
    (max_retries=5, honors Retry-After).

    Naive byte append works because tts-1 MP3 frames are self-contained.
    """
    chunks = chunk_text(text, TTS_CHAR_LIMIT)

    def render_one(chunk: str) -> bytes:
        response = openai_client.audio.speech.create(
            model=TTS_MODEL,
            voice=voice,
            input=chunk,
        )
        return response.content

    with out_path.open("wb") as f:
        with ThreadPoolExecutor(max_workers=TTS_MAX_PARALLEL) as pool:
            for i in range(0, len(chunks), TTS_MAX_PARALLEL):
                batch = chunks[i:i + TTS_MAX_PARALLEL]
                for part in pool.map(render_one, batch):
                    f.write(part)
```
