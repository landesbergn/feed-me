Spec · v3.31

Agent session page

Feed Me · 2026-08-25 · spec

When an agent starts driving a feed through WebMCP, take the person to a page built for watching that happen: a live activity log beside the episodes table, a status strip narrating the agent's current move, and prompt chips for steering it. The settings page stays the human-first home; /u/<secret>/collab becomes the human-plus-agent one. This is the "the site feels agent-driven" request, thought bigger than banners and flashes.

1 · Why

v3.29/v3.30 made tool calls visible (banner, flashes, live table), but the page being driven is still the settings page: a layout built around iOS setup instructions, with agent activity bolted on. Watching an agent work there feels like background automation. A dedicated view flips the frame: the person sees a running record of what their agent did, what it is doing now, and what to ask next, side by side with the episodes appearing. It is also the natural demo stage for the WebMCP Challenge's "human-agent experience" axis.

2 · What we're building

  1. New route GET /u/{secret}/collab rendering templates/collab.html: 404 on unknown secret, session cookie set (like settings), tracked as page_view with path="collab", GA included with ga_mask_location (the URL carries the secret).
  2. The page: header "You + your agent" with a live status pill (#agent-status-text); an Agent activity card (#agent-log, newest first, with an empty-state line); the episodes card reusing _episodes_section.html inside #episodes-section with the same 3s partial polling and pending-percent ticker as settings; a "Things to say to your agent" card of click-to-copy prompt chips (the v3.29 list); a Listen card (Apple Podcasts link + copy RSS); an exit link back to /u/<secret>. Two-column on wide screens, stacked on narrow. Loads /webmcp.js with defer.
  3. webmcp.js:
    • Path match extended to /u/<secret>/collab; the full feed toolset registers there too. refreshEpisodes builds its URL from the secret, not location.pathname.
    • Native agent mode: when #agent-status-text exists, status updates go there and to a persisted activity log (sessionStorage fmAgentLog, capped at 50, consecutive duplicates skipped) rendered into #agent-log. Without those elements the injected banner from v3.29 still applies, and activity still logs, so the record survives the hop. get_episode_status updates the status strip but is quiet in the log (polling must not spam the timeline).
    • Transitions: create_feed navigates to the new feed's /collab page. On the classic feed page, the first completed tool call hops to /collab after a short delay (never mid-call), once per page.

3 · Constraints and security

  • The collab URL carries the secret: GA must mask (ga_mask_location), the raw secret never reaches analytics values (_track attributes by hash), and the page adds no new endpoints or caps. Log entries are the script's own fixed strings, never tool inputs, so no injected content can enter the DOM through the log.
  • Navigation only ever happens between a resolved tool call and the next one; tools re-register on the destination page (the create_feed hop already proved agents follow this).
  • No em-dashes in any new copy; middot allowed.

4 · Testing

  • Route: 200 with the session markup (status pill, log, episodes section, prompt chips, exit link, webmcp include), cookie set, 404 JSON-free on a bad secret, GA location masked to /u/_, no em-dash.
  • Script contract: recognizes /collab, names agent-log / agent-status-text / fmAgentLog, keeps all prior pins (toolset, banner, reactions).
  • Manual (owner): create a feed via agent and land on collab; drive every tool from the classic page and confirm the hop carries the log.

5 · Out of scope

  • Voice controls or rotate on the collab page (the exit link reaches them); logging tool inputs or results into the timeline; multi-session log persistence (sessionStorage only); any backend change beyond the one route; the hackathon submission materials.

6 · Acceptance criteria

  • GET /u/<secret>/collab serves the session view with live episodes, activity log, prompts, subscribe, and exit; 404 on unknown secret; GA masked.
  • An agent creating a feed lands the user on collab; the first tool call on the classic page moves them there with the activity log intact.
  • Status polling never floods the log. Full suite green; CHANGELOG v3.31 and tag.
